# 終盤18教材への「なぜ？どう受ける？」理解チェック追加（2026-10-25）

## ねらいと範囲

既存の「🧠 なぜ？どう防ぐ？」を**終盤18教材すべてに追加**した。各教材につき2問（狙い・理由／相手の応手または結果の理解）で合計36問、各3択、日本語・英語対応。

これまでの23教材46問（戦術21×2＋基礎2×2）を維持し、今回の拡張後は**41教材・82問**。既存の「一手ためす」80教材と15名局の棋譜・FENは一切変更しない。

## 教材の対応

| 分野 | 代表的な理解の観点 |
|---|---|
| 基本の寄せ `eg_rook`, `eg_tworooks`, `eg_queen` | キングや2枚のルークによる逃げ道の封鎖、詰み後に合法な応手がないこと |
| ポーンの昇格 `eg_promote`, `eg_passadvance`, `eg_square`, `eg_connected` | 昇格記号、昇格と王手の区別、スクエアルール、連結したポーンの相互支援 |
| キング・ポーン `eg_opposition`, `eg_breakthrough`, `eg_activeking`, `eg_kingescort` | キングによる護送、突き捨て後の突破、キングの活動と勝ちの保証を区別する |
| 引き分けと昇格選択 `eg_stalemate`, `eg_underpromo`, `eg_wrongbishop` | 王手のない手詰まり、ナイト昇格後の駒不足、間違った色のビショップ |
| 高度な終盤 `eg_lucena`, `eg_philidor`, `eg_triangulation` | 4段目でのルークの橋、6段目封鎖と後方チェック、同じ配置の手番を変える三角法 |
| ルークの配置 `eg_rookbehind` | 通過ポーンの後方からの支援、原則は常に唯一の最善手とは限らない |

## 誤解を防ぐ出題方針

- **勝ち、引き分け、合法手のないチェックメイトを区別する。** 昇格しても自動的にチェックメイトになるわけではない。
- `eg_underpromo` はナイトでクイーンを取っても **キング＋ナイト対キングの駒不足の引き分け**。勝ちと誤説明しない。
- `eg_stalemate` は `Qg7#` と別案 `Qg6?` の違いを問う。`Qg6` は王手のない手詰まりで引き分けになることを回帰テストで検証。
- `eg_wrongbishop` は最終局面 `Kh6` がステイルメイトであることを盤面で検証。
- `eg_triangulation` は `Ke5 Kc6 Kd4 Kd7 Kd5` 後に同じ駒配置へ戻っても**黒番**であることを検証。
- `eg_lucena` と `eg_philidor` は特定の実演手順に言及し、全合法応手を強制するものとしない。最善同士の勝ち・引き分けの根拠は、既存のLichessテーブルベース記録を参照する。
- `eg_rookbehind`, `eg_kingescort`, `eg_activeking` は**一般原則の実演**であり、その一手が必ず唯一の最善手・強制勝ちと主張しない。

## 実装

- `js/lesson_reasoning_endgames.js` に18教材36問を分離。既存 `js/lesson_reasoning.js` の正答ID・保存状態に手を触れず、ロード直後に設問を統合する。
- `index.html` にキャッシュ版数付きで新しいデータを読み込む。既存の理解チェック画面とボタン、履歴 `animalchess_reasoning_v1` を使う。
- 終盤章の一覧に各教材「理解チェック 0/2〜2/2」、章全体に **0/36〜36/36** の進捗が出る。正解による理解度保存と既存の一手チャレンジの「習得」は独立したまま。
- 日英の3択は同一解答番号を共有。文言や正解表示は言語切替に追随する。

## 検証

- 全36問に公開教材の初期FENから始まる`evidence.line`（SAN列）を持たせ、`tools/test_lesson_reasoning.cjs`で全合法手、SAN正規表記、詰み／ステイルメイト／駒不足を検証。
- 保存済みテーブルベース全44局面（ルセナ16、フィリドール12、三角法16）のFENと勝敗カテゴリも、現行の教材から再生して照合。**新たなオンライン照会ではなく、2026-10-16に保存された証拠の再検査**である。
- `tools/test_full_game_browser.py` に18教材36問の可視性、誤答・正答、理解度の永続化、言語切替、ページ再読込、従来の習得記録の独立性を追加。
- 今回の変更で「未対応」とみなすブラウザテストは終盤章からオープニング章へ切り替えた。
- PRの最終コミットに対するGitHub ActionsのJavaScript・実ブラウザ／Web Worker回帰テスト成功をマージ条件とする。

## 注意事項

ここでの評価は教材中の実例の正しさを確認するものであり、すべての終盤局面の最善手を網羅したテーブルベース解析ではない。出題内容の定期監査や、実際にユーザーが理解しやすい選択肢の改善は引き続き必要。
