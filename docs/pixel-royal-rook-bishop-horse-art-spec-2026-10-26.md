# 動物チェス：ルーク・ビショップ・ナイトの実装直前スプライト仕様

2026-10-26 / ドット絵モード限定 / アート設計 v1

## A. 現行の実装と共通規格

すでに採用済みのライオン王・ネコ女王・ヒヨコ歩兵の本命グラフィックは **96×124px の透過PNG**。ゲームでは js/royal_sprite_loader.js が読み込み、盤面で縮小表示する。古い js/pixel_hd.js の40×52px描画はフォールバックであり、今回の作画基準ではない。

今回も同じ可愛い顔立ち・丁寧なドット絵・やや見下ろした正面寄りの視点で統一する。盤面そのものは従来どおり真上からの8×8正方形。動物以外の配置・背景・宴会場の構造は変更しない。

| 共通仕様 | 値 |
| --- | --- |
| 種類 | ルーク＝クマ（r）、ビショップ＝フクロウ（b）、ナイト＝**馬（n）** |
| キャンバス | 96×124px、RGBA8、背景透明 |
| 座標 | 左上 (0,0)、右下 (95,123)、座標範囲は両端を含む |
| 描画安全域 | おおむね x=6〜89, y=7〜115、足底 y=110〜115 |
| 透明余白 | 下端 y=116〜123 は透明。隣のマスに掛かる装飾はなし |
| 構図 | 正面寄り3/4。顔は大きく、胴体と手足は短め |
| 明暗 | 左上から弱い一灯。影・地色・明るい面を基本に3〜4階調 |
| 白チーム衣装 | ローズレッド #B9575D、明 #DA7D7F、影 #803F49 |

相対的な大きさは**表示上のシルエット目標**であり、CSSの幅を別々に変更するという意味ではない。同じ96×124の透明画像の内部で余白と造形を調整する。現行の盤上画像は高さ最大84%、幅最大84%という制限に従う。実際の約40pxのマスで確認する。

**可愛さの優先順位**は、ふっくらした頬と顔の丸み、目と口のバランス、耳・羽・たてがみ、短い手足、最後に衣装。宝石・装飾・意味のない反射・ランダムなディザ・背景追加で品質をごまかさない。元の3体をイラスト単体で並べたときに世界観が揃うことを第一とする。

## E. 通常・目閉じ・宴会ポーズ

現行のロイヤル画像ローダーは通常（open）と目閉じ（closed）、馬車専用16×20だけに対応している。宴会の飲食・睡眠は既存CSSと既存アイテムで動く。**第一実装の必須素材は通常6＋目閉じ6＋馬車6＝18枚**でよい。

目閉じ差分では目と周囲の頬以外の位置を固定し、まばたきした瞬間に駒全体が揺れないようにする。睡眠中はCSSが90度回転するので、画像自体を横向きにしない。将来専用の eat/drink/sleep 3動作を追加するなら、3役×2陣営×3動作の18枚が増える。料理とカップは描き込まず、二重表示を防ぐ。

## F. 現在のアトラスと今後の組み込み

現行 js/royal_sprite_loader.js は型配列 k/q/p、白黒の6列、列幅96、縦は通常124・目閉じ124・乗客20の合計268で、アトラス寸法は576×268。完成時は既存の6列を保ち、末尾に r/b/n×白黒を追加して **12列・1152×268** にする方法が安全。

順序は k/q/p/r/b/n と固定。通常 row y0〜123、目閉じ y124〜247、乗客 y248〜267。画像のデコード、サイズ、切り出し範囲を全列検査し、成功したときだけ描画を一括切替。失敗したら従来の PixelHD のフォールバックを維持し、中途半端な混在状態を公開しない。

PNG素材名：
- pieces/w_r_bear_rook.png, pieces/b_r_bear_rook.png
- pieces/w_b_owl_bishop.png, pieces/b_b_owl_bishop.png
- pieces/w_n_horse_knight.png, pieces/b_n_horse_knight.png

目閉じは poses/blink/、乗客は riders/ に同じ名前で作成する。すべて透過PNG。実装段階では js/sprites.js の既存 API と馬車の到着・宴会状態機械、8×8マスの当たり判定、学習履歴、FEN/SANを変更しない。

種名に注意：ドット絵データ SPRITE_DATA.chars.n.name は現状「うま」、現行アプリのイラストモード名称も horse を使用する。一方、js/pieces.js には別モード用の deer / しかさん 表記もある。**今回の馬への変更はドット絵モード限定**。他モードを無断で変更しない。古い設計文書の「鹿のナイト」は今回の決定で上書きする。

## G. レビューと合格条件

制作順：①馬の白黒を試作 → ②クマ白黒 → ③フクロウ白黒 → ④既存3種と一緒に白黒計12体を比較 → ⑤目閉じ6枚 → ⑥馬車乗客6枚。

検証は実際の320px盤（1マス40px）、390px幅、デスクトップ、宴会のゲスト幅40pxで行う。白マス・黒マス双方に置き、耳・頭飾り・鼻先がマス境界に触れないことを確認する。ポーンは引き続きほかより小さい。

宴会は0/1/8/16体、飲食、まばたき、寝転がり、馬車からの到着、待った、再開、画面反転、表示モード切替、動作軽減を検証。別のシンプル／ミニチュアモード、AI、Web Worker、教材も既存の回帰テストを通す。

合格判定：
- クマは丸耳と城壁帽、フクロウは2つの目と縦帽子、馬は耳・鼻面・たてがみで判別可能。
- 馬に枝角はなく、いずれもキングより少し控えめな大きさ。
- 既存のライオン・ネコ・ヒヨコと同じ可愛さ・輪郭・ドット密度。
- 馬車で宴会へ行き、飲食したり寝転がったりする物語はそのまま。
- PR→GitHub Actions→main→GitHub Pages確認の順に公開。

**この文書は素材制作用の仕様であり、PNGの完成や公開実装を主張するものではない。**
