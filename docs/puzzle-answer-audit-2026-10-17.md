# パズル別解・誤判定監査（1017_006）

## 目的

ユーザーから、問題「ダブルチェックをかけよう」で `Bc6+` が不正解になるとの報告を受けた。旧版は戦術38問それぞれに単一SANを登録しており、**戦術として同じ意味になる他の合法手**を見落としていた。今回、38問について局面を列挙し、戦術の成立条件に照らして正解手を再検査・修正した。

## 確認できた正解漏れ

| ID | 従来の正解 | 新規に採用した別解 |
| --- | --- | --- |
| `tactic-double-check` | `Bg6+` | `Bc6+` |
| `tactic-doublecheck-knight` | `Ne6+` | `Nc6+` |
| `tactic-fork-queen-minors` | `Qe4` | `Qb4`, `Qh4+` |
| `tactic-pin-queen-knight` | `Qc5` | `Qc1`, `Qc3` |
| `tactic-discovery-knight-queen` | `Nf6+` | `Ng5+` |

合計7手の正解漏れを修正。戦術・ルール問題38問の正解登録は **38手 → 45手**。

## 盤面・解説の修正

1. `tactic-pin-queen-king`：白ルークがもともとg列にいて黒クイーンが初めからキングにピンされていたため、a5からg5へ移動して新しくピンを作る盤面に変更。h4の白ポーンがルークを守る。
2. `tactic-pin-bishop-knight`：白ビショップの元の位置がすでにピンのライン上だったため、h1からe4へ移動する盤面に変更。
3. `tactic-pin-bishop-king-2`：同様に元の位置でピンが成立していたため、b1からe4へ移動する盤面に変更。
4. `tactic-pin-queen-rook`：ルークをピンする既存の問題では、黒ルークが移動後の白クイーンを取れてしまい、戦術として不適切だった。敵ルークを敵ナイトに置き換え、`tactic-pin-queen-knight`（クイーンでナイトをピン）として再設計した。c1・c3・c5のいずれでもナイトに絶対ピンが成立する。
5. `tactic-fork-queen-minors`：斜めからの正解もあるため、「縦の両取り」という限定表現を改め、縦と斜めの両方を日英解説に明記した。
6. `tactic-rook-underpromotion`：`c8=Q` はステイルメイト、`c8=B` と `c8=N+` は駒不足による即引き分けであり、クリア条件（引き分けを避ける）に合わない。唯一の正解は `c8=R` であり、日英解説に理由を追記した。

## 検証方針

- `tools/audit_alternate_tactics.cjs`: **38問**の初期局面で全合法手を列挙し、各テーマの盤上の成立条件を独立計算して、登録SANと集合比較する。未登録の正解、登録されている不適切な正解、開始局面ですでに成立しているピンを検出してテストを失敗させる。問題ID追加時は対応する条件の追加を要求する。
- `tools/test_puzzle_alternatives.cjs`: 実際の `puzzleTryMove()` を使い、45件の戦術正解手がすべてクリア扱いになることを検証。ダブルチェックでない王手や引き分けになる昇格など、合法だが不正解である7手が通らないことも確認する。
- `tools/test_puzzle_alternatives_browser.py`: ChromiumにHTML/JSを直接注入し、画面の駒クリックで新たな別解7手を実行し、クリアできることを検証。`Bd5+`（単一王手）は不正解のまま。
- `tools/test_mate_solver.cjs`: メイト42問の最短強制詰み、相手の全合法応手と継続解答木を照合。42問、178継続局面。
- 既存のパズル品質、戦術検証、UIナビゲーション、駒描画などの回帰テストも実行済み。

`python-chess`による別実装での再検証は、この実行環境にモジュールがないため未実施。ブラウザテストは直接注入方式であり、通常のHTTPサーバー配信に固有の挙動は検査していない。

## 今後のパズル追加の注意

新規の戦術問題は「指定の一手が合法である」だけでは不十分。意図した駒への攻撃・二重王手などが実際に成立し、同じ条件を満たす**全合法手**が正解候補に登録されることを必ず検証する。駒の配置によっては、開始時点で戦術が成立していたり、駒を取られて有効な戦術になっていない場合があるので、その点も確認すること。
