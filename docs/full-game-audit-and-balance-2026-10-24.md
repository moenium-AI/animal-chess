# 動物チェス：ゲーム全体の修正とAI棋力バランス試験（2026-10-24）

## 基準
GitHub `main` の `141e6584c9e4980abaf7232c1c620e1924d081f6` を基準。
チェスルールの一般的な外部ライブラリは変更しない。

## 修正済みの確定不具合

- **A-01**: チェックメイト後の予約タイマーを世代IDと盤面オブジェクト／FENでガードし、対局変更・待った・学習／パズル移行時に取消。古い終了モーダルが次局へ出る問題を解消。
- **A-02**: CPUとヒントの同期探索を専用Web Workerに隔離。新しい対局／パズル／学習へ移るとWorkerを terminate し、古い返答を破棄。Workerが利用できない環境では旧式の探索へフォールバック（その場合はUIブロックの可能性が残る）。
- **A-03**: 昇格／終了モーダルをARIAダイアログ化。初期フォーカス、Tab／Shift+Tab循環、Escape閉鎖とフォーカス復帰を追加。
- **A-04**: 保存設定の復元をホワイトリスト方式に変更。列挙値、level 1〜10、boolean、BGM曲番号を型検証し、異常値を無視する。

## ブラウザ実行試験
- 制限されたローカル環境ではHTTPがブロックされるため、同じソースをインライン挿入し、Web Workerは実際のBlob Workerとして実行。
- 待機中の終局ダイアログが新局に表示されないことと、正しい終局ではモーダルが開くことを確認。
- 昇格のフォーカス移動、Tab循環、Escapeキャンセルと昇格確定を確認。
- 不正保存値で色とレベル等の既定値が復元されることを確認。
- Workerのヒント計算中の描画設定変更 **34ms**、CPU思考中の新対局 **15〜18ms** 程度で応答。元のメインスレッド計算では最大約3秒の停止が観察されたが、端末・局面が異なるため厳密な同条件速度比較ではない。
- Workerが合法手を返し、破棄した古いCPU着手が新局へ混入しないことを確認。
- 新規GitHub Actionsは実際のlocalhost HTTP経由でWorkerを読み込み、Chromium上で同様の検査を実行する。CIの合格が確認されるまで完了としない。

## 棋力バランスの測定方法
- 10レベルすべてに共通の歴史的名局の中盤局面5件（モーフィー「オペラ座」、アンデルセン「不滅」「常緑樹」、ラスカー対トーマス、マーシャル対レビツキー）を利用。
- 対局エンジン本体の手を、別プロセスのStockfish 16で深さ8まで評価。選んだ指し手により評価が何センチポーン（cp）下がったかを記録。
- PRNG初期seed=20261024。バッチ実行に分割したため、バッチ間でStockfishの内部探索履歴、CPU負荷が厳密一致ではない。

## 判断と次の対策

**10段階の強さが単調増加する保証は、今回のテストでは得られなかった。**

- Lv8〜9の平均評価損失はLv1〜3より小さかったが、Lv10は5サンプル中に533cpの大きな失点があり、平均が188cpとなった。
- Lv10の計算時間は約2.1秒でLv9の約1.7秒より長かった。深く考えることが、すべての局面で良手につながっているわけではない。
- 選択局面は歴史的な名局由来で難易度が高く、チェス初心者を想定した10段階のEloは推定できない。
- 少なくとも各対戦レベルの定跡外での自然な手を対象に、棋力差を拡大する設計（探索終端の王手処理、反復局面、候補手の再検証）と、各色・複数seedでの自動対局が必要。

**重要**：本測定は棋力の合格判定ではなく、バランスの改善課題を発見するための監査。弱いAIの有益な誤りと、理由のない大駒損は区別して調整すべき。
